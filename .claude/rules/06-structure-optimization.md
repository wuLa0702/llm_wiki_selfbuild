> 📌 **双位置**：本文件 `.claude/rules/`（**权威，自动加载**）；目录分层以 `12-backend.md` 为唯一载体（本文件不重复目录表）
> 📌 **与现役 rules 的关系**：冲突处以本文件裁决为准（阈值/异常/依赖等已统一）；现役 `01-coding-style.md` 已回写同步（80/800 阈值）
> 📌 **适用范围**：`src/` 全部 Python 代码（新增与重构均适用）

## 1. 阈值与统计口径

**有效业务代码行** = 总行数 − 注释/docstring − 空行 − 单独导入行 − 类型注解 − 装饰器 − 常量定义区。

| 线 | 阈值（有效业务代码行） | 动作 |
|----|------------------------|------|
| 文件关注线 | > 750 | 标记拆分候选，人工评估 |
| **文件强制线** | > **800** | **必须拆分**（单一职责/业务能力维度，禁随机切块） |
| **函数强制线** | > **80** | **必须拆分解耦**（不再"考虑"） |
| 函数质量底线 | > 160 | 拆分失败信号：拆解后仍 >160 → 继续拆 |

**底层函数豁免**（必须拆分例外）：全局通用工具 / 基础算法（tokenizer、分页）/ 通用解析封装。
**不豁免**：业务逻辑 / Agent 编排逻辑 / 流程控制逻辑。
豁免函数必须在 docstring 声明"底层函数，按规范豁免"（供校验脚本白名单）。

## 2. 目录与分层

目录结构与依赖方向见 `12-backend.md`（`main → core → {tools, llm, db}`，禁止反向依赖），本文件不重复。

**跨层禁令**：
1. 只能上层调下层：`main → core → {tools, llm, db}`；core/llm 为公共底座
2. **禁跨多层跳跃**（如 main 直调 db、core 直调第三方 SDK）
3. **业务模块禁直接调用底层存储/第三方 SDK**——一律经 adapter/repository 中转

## 3. 常量与路径

- **常量**：跨文件共用 → 集中常量模块（"用两次就抽"）；单文件私有 → 模块头部常量；函数内禁硬编码魔法值
- **路径**：全部集中 `src/utils/path_resolver.py`（dev/打包自适应）；新增数据目录必须登记；**禁裸字符串路径拼接**（`str + "/"`），统一 pathlib

## 4. 日志与异常

- **注释 ≠ 日志**：注释管开发阅读，日志管线上排查——关键节点/入参出参/异常**必须有日志**（统一中间件覆盖，函数内仅异常分支与关键状态补打）；禁 print 调试
- **异常四分类**：
  | 分类 | 处理 |
  |------|------|
  | 可重试（网络/超时/限流）| 重试后仍失败 → 降级 |
  | 不可重试（参数/状态/不存在）| 直接返回业务错误码，不重试 |
  | 业务异常 | 业务错误码 + 降级/默认兜底 |
  | 系统异常（未知内部）| 记 error 日志 + 按链路矩阵降级 |
- **禁超大范围 try-except 裸捕获**（`except Exception` 包整段业务）：捕获必须精确到异常类型、必须处理（记录/转换/降级），不吞异常、不盲抛
- 除 LLM 主链路外，**不因单点失败断流**——降级 + 默认兜底 + 日志留痕

## 5. 依赖与导入

- 禁循环 import（出现立即重构）
- 禁全局 `*` 导入（全部显式导入）
- 第三方 SDK/LLM/中间件统一单例封装（`src/llm/` 等）——业务代码禁直接 `new` 第三方实例
- 导入顺序：标准库 → 第三方 → 项目内部，每组空一行

## 6. 文案与可测试性

- **错误文案**：统一中文 + 冒号分隔（`失败原因：xxx`）；API 层禁裸字符串错误；ErrorResponse 统一字段
- **可测试性**：每个业务/工具函数必须有对应测试（`test_<模块>.py`，随写随测）；外部依赖全部可 mock（构造注入式）；LLM 全 mock（20-testing 纪律）
