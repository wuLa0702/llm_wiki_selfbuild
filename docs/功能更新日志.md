## 1. 用途与维护规则 🔴 v1

**用途**：记录"什么时候新增/完善了什么功能"——按功能域标注 **git 版本（commit 短哈希）+ 更新时间范围**。对比两次查看间隔的变更，无需全量翻代码或读功能源码，git log 命令即真相源。

**维护规则**（co-creator 2026-08-10 拍板：双表 + 阶段性批量 + commit 短哈希）：

| 规则 | 约定 |
|------|------|
| 触发时机 | **阶段性批量**：每批功能提交收尾时更新（约 1 分钟）；不逐 commit 更新 |
| 版本号 | **commit 短哈希 8 位**（可 `git show <hash>` 回溯）；不引入 tag 体系 |
| 信息源 | **git log 命令**（§2 模板），禁止翻代码/读源码确认 |
| 流水粒度 | §3 一次功能批次一行（同批多 commit 合并记，版本列记末位 hash） |
| 对比流程 | 上次查看记下最后版本号 → 打开 §3 过滤该版本之后的行 → 需要核对时 `git log <旧hash>..<新hash> --oneline` |
| 更新动作 | 新增一行到 §3（倒序，置顶）→ 同步更新 §4 对应功能域行的最近更新/版本/时间范围 |

## 2. git 命令模板 🔴 v1

```bash
# 查某日期后的功能/修复/重构提交（变更流水反填素材）
git log --since="2026-08-01" --pretty=format:"%h|%ad|%s" --date=format:"%Y-%m-%d" --grep="feat\|fix\|refactor" --regexp-ignore-case

# 按功能域关键词过滤（如 agent）
git log --pretty=format:"%h|%ad|%s" --date=format:"%Y-%m-%d" --grep="agent"

# 版本区间对比（上次查看版本 → 当前）
git log <旧hash>..<新hash> --oneline

# 某版本详情回溯
git show <hash> --stat
```
