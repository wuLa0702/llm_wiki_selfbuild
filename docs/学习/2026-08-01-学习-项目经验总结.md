## 二、核心方法论（最重要，权重最高）

### 1. 功能堆叠有止境，生产级聚焦才是分水岭
功能永远做不完。核心闭环跑通后，停止堆功能，转向**生产级短板分析**（持久化/备份/并发/鉴权/可观测）。Demo → 生产级的跨越比加功能更打动面试官，也是项目现在的真实价值所在。
（源：`notes/feature-philosophy-production-focus.md`）

### 2. 引导式面试复盘：把「做完了」变成「讲清楚了」
每个 Phase 结束做复盘：AI **只问不答**（苏格拉底式），用户口述后逐条核对 ✅/⚠️/❌。价值：表达是用户自己的，不是背 AI 稿；同时暴露「做完了但讲不清」的盲区。
（源：`notes/dev-process-conventions.md`）

### 3. 对标三步法，不凭感觉对比
① AI 梳理参考项目架构出模块清单 → ② 逐模块分类（我没有的 = 开发候选 / 我有的 = 比实现差异）→ ③ 输出差距报告调整优先级。先判**性质差异**，只借鉴与自家技术栈/形态相符的，明确「不必学」清单。
（源：`notes/benchmark-methodology.md` + `notes/nashsu-comparison.md`）

### 4. 高频路径增量优先，全量 N² 是性能炸弹
凡算法先问调用频率：ingest/query 等高频路径**必须增量**（只算新增节点，O(N²)→O(N×M)），全量只放低频（定时/手动）。这是从全量关联度计算撑爆性能的教训提炼的通用原则。
（源：`notes/incremental-computation-lesson.md`）

### 5. 手写训练纪律：核心亲手写，样板交给 AI
Agent 核心机制（State/节点/边/循环/多智能体路由）必须**先看懂思路 → 清空代码 → 独立手写复现**；样板胶水（初始化/适配/配置）才用 AI 提速。第一个 Demo 强制手写，成功复现 1~2 次后放开。核心逻辑不亲手写，面试被追问细节必然露馅。
（源：`.claude/rules/02-hands-on-training.md` + `notes/agent-memory-hands-on.md`）

### 6. 决策用评分矩阵，不用直觉
模型选型实例：成本 25% + 编码 20% + 推理 20% + 中文 15%… 多维加权评分 → 结论 V4-Flash 主用（8.45 分）+ Pro 兜底。**成本差 12 倍、质量只差 1-3 分**——量化后决策不再摇摆。
（源：`notes/deepseek-model-choice.md`）

### 7. 市场行情是路线图的输入
2026-07 面试门槛已从「有本地 Demo」升到「线上可部署的多 Agent 落地工程」（纯本地 Demo 淘汰率 65%）。据此反推项目要补：公网部署、可观测、压测、沙箱。行情变化 → 路线图调整，而不是路线图自嗨。
（源：`docs/学习/2026-07-27-学习-AI-agent面试市场.md`）

## 三、踩坑教训（血泪清单）

1. **LLM 生成输出不可信 → 源头硬约束**：LLM 生成 wikilink 用裸名导致 165 个断链误报。教训：约束要前置在 prompt（「引用的 `[[path]]` 必须是本次实际创建的页面」），事后 lint 修复是兜底不是方案。
2. **一键自动修复会误杀有效数据**：`lint/fix` 直接删除 165 个链接，把格式不匹配的**有效链接**也删了。教训：破坏性自动修复必须分级（建议修正 → 存根 → 补充），删除不是第一选项。
3. **技术债会集中爆雷**：后端审查一次揪出 11 个问题——main.py 1106 行违反自己定的规范、30 个路由手写依赖、无全局异常处理器。根因统一是「功能优先、规范让路」。教训：核心闭环后必须设**生产化整改阶段**统一清债。
4. **超时参数默认值害人**：15s 超时 + 1 次重试吞掉 52KB 源文件的生成调用；改为 120s/0 重试一次成功。教训：LLM 调用超时要按 prompt 规模估，别用框架默认值。
5. **手写 LangGraph 三大 Bug 模式**：① Message 对象当 dict 用（用 `hasattr`+属性访问）；② 条件边返回值不匹配 `add_node` 注册名（字符串必须精确一致）；③ State 字段冗余 + 类型不精确（只声明运行时必需的，`list` → `list[BaseMessage]`）。
6. **快速迭代期的「规范让路」是债的根源**：每个「先跑通再说」都会变成后续的修复成本。规范先立（哪怕宽），比后补便宜。
7. **frontmatter 渲染坑**：`markdown.markdown()` 不解析 YAML frontmatter，原样显示在正文——渲染链路要显式处理 frontmatter。

## 四、流程约定（已固化的习惯，保持）

1. **提交前确认**：commit 前先列改动文件清单 + 消息草案，等确认再执行；wiki/、notes/ 默认不入库，防隐私泄漏。
2. **中文标题/文件名**：wiki 页面用中文标题和文件名（`entities/注意力机制.md`），英文术语保留。
3. **复杂能力设「不做判据」**：核心闭环未稳 + 基础设施未全 + 调试能力不足 → 不做（例：自修复 Loop 排到优化期，并写清何时才做）。
4. **笔记 P0-P4 分级落地**：存量笔记的待办用分级清单管理，避免「记了不执行」。
5. **每个 Phase 结束**：引导式面试复盘（见方法论 2）。

## 六、面试经验（2026-07 行情）

- **行情巨变**：纯基座算法岗收缩，Agent 落地岗爆发（45% 全为 Agent）；纯本地 Demo 过不了简历初筛（淘汰率 65%）。要求：线上可访问 + 完整工程部署 + 能讲多 Agent 落地闭环 + 可观测/压测/沙箱。
- **求职策略迁移**：简历删过时微调内容、突出 LangGraph 多智能体落地工程、避开纯基座岗、主攻数字员工/办公 Agent/SWE 团队（通过率与薪资双高）。
- **面试话术速查**：每个技术改进都能讲「为什么不」——「为什么不把 X 返回给 Agent」「为什么不用语义切分」（Wiki 整页是知识单元，chunk 只做索引；语义切分是过度工程，heading 切分零成本零 LLM 调用）。

## 七、工程技巧（简要，低权重）

- **Git 批量 rebase squash**：先建备份分支 → 处理 untracked 冲突 → stash；todo 文件用 `GIT_SEQUENCE_EDITOR` 注入避免编辑器交互；同组冲突**永远取 incoming**（后者修复前者）；中文消息用 `fixup + exec git commit --amend` 而非在 todo 里写中文。32 提交 → 12 提交，零人工编辑器干预。
- **单日大功能交付模式**：持久化 + 审批 + 摘要三个能力一天内按「图演进」顺序落地（MemorySaver → +SQLite → +approve → +summarizer），每个能力独立 commit 可回溯。
