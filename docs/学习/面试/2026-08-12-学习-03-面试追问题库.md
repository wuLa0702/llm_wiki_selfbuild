## 第一轮：项目深挖（60-90 分钟，刷掉 60%）

> 面试官视角：这一轮全从简历项目出发连环追问，**模糊回答直接扣分**，聊不出 Trade-off 就挂。考察重点：记忆机制细节、成本控制、模型选型、线上故障排查、具体数字。

### A. 项目动机与定位（开场 5 分钟）

**Q1. 这个项目为什么做？解决了什么问题？**
> 回答要点：知识管理场景的真实痛点——资料收了不看、问了不答。Karpathy 的 LLM Wiki 理念启发：把"收藏"变成"编译"。我自己实际使用中迭代（笔记哲学：功能不多但每个都是实际用出来的）。
> 深层：面试竞争力 + 系统掌握 LangGraph 工程化，但**先说业务价值**，再说个人成长。

**Q2. 和市面上的知识库/RAG 产品比，差异在哪？**
> 回答要点：① 编译器 vs 解释器（见 02 亮点 1）② vs nashsu/llm_wiki（Tauri 桌面、开箱即用）→ 我们强在 API 可编程性 + Python 全栈 + 完整安全模型。差异化不是"做得不一样"而是"选择不一样"——技术选型导致设计取舍不同。
> 详细：`docs/rag-wiki-comprehensive-comparison.md` #13；`notes/differentiation-strategy.md`

**Q3. 项目做到什么程度了？完整吗？**
> 回答要点：完整闭环——摄入/查询/图谱/Agent 对话/前端/打包全通。754 后端测试 + 81 前端 + 22 E2E。数字要准（见 01 §6）。
> 补充：诚实补短板——向量搜索默认关、LangSmith 未接、多 Agent 未做，但都有规划。

### B. 摄入与编译（技术深挖）

**Q4. 摄入的两步 CoT 为什么是两步不是一步/三步？**
> 回答要点：一步会遗漏非关键实体、忽略与现有 wiki 关联、跳过内容矛盾；三步在当前量级是过度设计；管道可配置、量级上去可扩（见 02 亮点 2）。

**Q5. 摄入失败怎么办？LLM 输出不稳定怎么兜底？**
> 回答要点：重试 1 次 → 降级 ingest_simple 单步模式；输出解析容错（容忍 ```json 围栏）；Pydantic 校验；写入前校验 + 写入后 Lint 双保险。

**Q6. token 成本怎么控制？**
> 回答要点：SHA256 增量缓存（改才重编译）；index-summary 注入省 ~80% token；两步结构化输出减少无效生成；token 用量逐次落库可审计；模型选 Flash（1/12 成本）。
> 详细：`docs/rag-wiki-comprehensive-comparison.md` #相关 + `notes/deepseek-model-choice.md`

**Q7. 源文件格式支持哪些？怎么扩展？**
> 回答要点：md/txt/pdf/docx/html/csv/pptx/xlsx 多解析器（ReadTool 按扩展名分发）；新增格式 = 加一个 parser，接口不变。

### C. Agent 核心（重点中的重点）

**Q8. 手写 StateGraph vs create_react_agent？**
> 回答要点：控制粒度——自纠错/审批/记忆注入都要插在循环特定位置；手写代表真懂 add_messages、conditional_edges、interrupt/Command（见 02 亮点 3）。

**Q9. 状态怎么管理？State 里有什么？**
> 回答要点：`AgentState(TypedDict)`：messages（Annotated + add_messages 增量追加）、attention_sinks、working_memory（自定义 reducer 按槽合并去重）、step_count、executed_actions、self_correction、current_intent。7 个字段，逐个能讲。
> 详细：`docs/agent-architecture-diagrams.md` §1.4

**Q10. 工具调用的错误处理？工具连续失败怎么办？**
> 回答要点：三层自纠错就是干这个的——重复调用去重拦下、空输出质检拦下、反思修正计划；熔断 15 步兜底；全部失败收尾给用户可理解的回答而不是报错。
> 面试官视角补充：这是 2026 稀缺人才第一条——"把 Agent 做稳"的异常处理能力。

**Q11. 意图分类是干嘛的？为什么用规则优先？**
> 回答要点：greeting/clarification/tool_operation/knowledge_query/chit_chat 等分类；规则匹配零 LLM 成本，兜底才调 LLM；闲聊意图跳过工具绑定省 token；分类结果注入 LLM 输入（SystemMessage 形式，不污染 messages）。

**Q12. 多轮对话怎么隔离的？两个用户同时聊会串吗？**
> 回答要点：thread_id 隔离；MemorySaver 按 config 分会话；SQLite 按 thread_id 存取；interrupt 挂起时只等 resume 不接收新消息。并发是 P1 已知项（单机场景够用）。

**Q13. 摘要压缩后上下文丢了怎么办？**
> 回答要点：摘要生成时注入 sink + WM 上下文，关键信息跨摘要存活；摘要本身是 SystemMessage 保留在消息列表；阈值 40 条非系统消息触发。
> 详细：`docs/agent-architecture-diagrams.md` §1.6

**Q14. 冷启动/重启恢复怎么做？**
> 回答要点：MemorySaver 运行时 + SQLite 持久化混合；启动检查 MemorySaver 有无消息，无则查 SQLite load_thread 回灌（消息 + sinks + WM）；归档会话只回灌摘要 + 提示"恢复自归档"。
> 详细：`docs/agent-architecture-diagrams.md` §2

**Q15. 失效工具调用降低 60% 怎么来的？有评测吗？**
> 回答要点：裸 ReAct vs 三层自纠错在测试集上的工具调用次数对比；**能复现的数字才说，说不清就承认是开发期对比估算**。2026 面试红线：模糊数字直接扣分。
> 诚实话术："对比基线是同一测试集裸 ReAct 的调用次数，三层叠加后约降 60%，测试集可复现——但这是开发期对比，没有上生产压测。"

### D. 检索与数据

**Q16. BM25 中文分词怎么处理的？**
> 回答要点：CJK Bigram 二分分词（中文无空格，bigram 是最简可用的切分）；标题 3× 加权；FTS5 对话搜索同样有 CJK 降级 LIKE 方案。

**Q17. 混合检索的 RRF 为什么不用权重调参？**
> 回答要点：RRF = 各排名的倒数排名和，天然免调权重，两个检索器分数尺度不同也能直接融合；比加权和鲁棒。

**Q18. 知识图谱的数据从哪来？是 LLM 生成的吗？**
> 回答要点：wikilink 正则解析，纯确定性零 LLM 成本；4-Signal 权重关联度 + Louvain 社区 + 洞察引擎（惊喜连接/知识缺口）。回答时可画图。

### E. 工程与部署

**Q19. 项目怎么部署的？有线上吗？**
> 回答要点：诚实——本地 + PyInstaller 桌面打包（单实例锁 + 崩溃兜底 + %APPDATA% 数据目录）；无公网部署。2026 行情线上部署是硬要求，主动承认并讲规划（自托管 workflow 已写，下一步上云）。
> 详细：`docs/release-guide.md`

**Q20. 出过什么线上问题？怎么排查的？**
> 回答要点：挑 2-3 个真实 bug 复盘讲（比编一个完美故事强）：
> ① wikilink 路径归一化 bug（路径分隔符 Windows/Linux 不一致导致断链）② LLM 超时无重试（加超时 + 重试层）③ async/sync 混用阻塞事件循环（asyncio.to_thread 包裹）④ Windows 删库文件句柄占用（改表级 DELETE）。
> 详细：`.learnings/interview-notes.md`（真实复盘都在这里）

**Q21. 测试怎么写的？LLM 怎么测？**
> 回答要点：pytest + mocker 全 mock LLM；tmp_path 文件系统；:memory: SQLite；边界覆盖（空/大文件/特殊字符/路径穿越/权限拒绝/LLM 超时/空回复/格式错误）。754 个测试。

## 第二轮：系统设计（60-90 分钟，刷掉 60%）

> 面试官视角：从 0 到 1 搭商用 Agent 系统，边画架构图边追问。考察：模块拆分、任务调度、异常容错、工具权限矩阵、Prompt 注入防护、成本与并发。

**Q22. 如果让你从 0 设计一个商用 Agent 系统，模块怎么拆？**
> 回答要点：照搬自己项目的四层（perception / planning / memory / action）+ 三个支撑（工具层 / 持久化 / 可观测）。理由：感知与规划分离——意图分类不阻塞主线程；记忆独立成层——多 Agent 时可共享；工具注册表——权限元数据与实现解耦。**画图讲**，这就是你项目架构的"元"回答。

**Q23. 任务调度：简单/复杂任务怎么区分？拆解粒度怎么控？**
> 回答要点：意图分类先粗分（闲聊直答不调工具）；复杂任务在规划层拆子步骤；粒度控制 = token 成本权衡——拆太细费 token，太粗效果差；当前单 Agent 内循环即调度，多 Agent 时 supervisor 路由（规划已写，见 `docs/agent-architecture-diagrams.md` §4.2）。

**Q24. 异常容错体系怎么设计？重试/回滚/重新规划的触发条件？**
> 回答要点：重试有成本上限（重试 1-2 次不无限）；回滚有状态保存点（checkpoint）；重新规划有触发条件（质检失败 + 反思 revise）；全部兜底降级路径（结构化输出失败 → 单步；LLM 挂 → 返回已有缓存/友好错误）。**核心：先定义"什么时候该停"，再定义"怎么重来"**——2026 面试官最看重的失败边界意识。

**Q25. 工具权限矩阵怎么设计？**
> 回答要点：三层——目录隔离（raw 只读/wiki 可写/src 只读）→ 工具级（只读自动放行，requires_approval 默认 fail-closed）→ 页面级（restricted 标记 + bcrypt + 24h token）。操作审计：operation_log 表记录所有写操作。

**Q26. Prompt 注入怎么防？**
> 回答要点：诚实 + 方案。当前：内容来自用户自己的 raw 素材（受信边界内），风险面小；内容消毒（LLM 输出禁 script/iframe）；方案：注入检测层 + 工具输入校验（读页时 strip 系统指令）+ 权限最小化（只读工具天然限注入危害）。2026 行情：Prompt 注入检测是稀缺技能点，讲出"我知道它存在 + 边界在哪 + 怎么补"就够。

**Q27. 单用户日均 token 成本多少？百万用户怎么控成本？**
> 回答要点：诚实——未上生产没真实数字，讲设计：Flash 模型（1/12 成本）、摘要压缩（40 条后 10 条）、意图分流（闲聊不调模型绑定）、缓存（摄入 SHA256 + 图谱签名）。百万用户方案：模型分层（简单意图用小模型）、并发队列、结果缓存。**没数字就讲控制机制，别编数字。**

**Q28. 防恶意刷？限流怎么做？**
> 回答要点：诚实——单机场景未做限流；方案：token 配额 + 频率限制中间件 + 队列背压。2026 行情成本控制是高频追问，至少要有方案。

**Q29. 可观测性怎么设计？**
> 回答要点：现有：SSE 事件流（用户可见工具过程）、operation_log 审计、token_usage_log、/health 监控、前端错误上报 .logs/frontend.log、日志 tail 接口。缺口：LangSmith 未接（3 行 .env 可启用，已留接口）。2026 行情：89% 团队做 Observability，这是加分题。

**Q30. 多 Agent 怎么做？什么时候该上多 Agent？**
> 回答要点：判断——单 Agent 能完成的不用多 Agent（当前项目定位就是单 Agent 做深）；上多 Agent 的场景：工具面大、需要专职角色、可并行子任务。方案：2026 官方推荐 Subagents as Tools（主管通过 @tool 调子 Agent），基础设施（记忆层/注册表/持久化）可直接复用。详细：`docs/agent-architecture-diagrams.md` §4.2-4.4。
> 避坑：不要主动贬低单 Agent 项目，2026 行情"只会单智能体"是淘汰点——所以**讲清楚"我为什么先做深单 Agent + 多 Agent 的路径在哪"**，这是有判断力的表现。

## 第三轮：认知与定级（30-50 分钟）

> 面试官视角：聊赛道判断、个人差异化、1-2 年瓶颈预测、从 0 到 1 带业务怎么排优先级。没有标准答案，看认知。

**Q31. 你怎么看 2026 的 Agent 赛道？**
> 回答要点：三段式——① 市场：基座缩 HC、Agent 爆发（WAIC 6 万岗 45% Agent、DeepSeek 80% 岗提 Agent），供需 1:8，企业从招研究员转向招能落地的工程人才；② 技术：单 Agent 工程化（记忆/容错/审批/可观测）是基础能力，多 Agent 编排是下一跳，MCP 在统一工具生态；③ 判断：做 Agent 的和做 Agent 基础设施的会分化，工程落地能力 > 模型理论。来源：`docs/ai-agent-interview-market-2026-07.md` + interview/05。

**Q32. 你的差异化优势是什么？**
> 回答要点：① 完整闭环工程（前后端 + 测试 + 打包 + 安全模型），不是 demo；② 手写核心（StateGraph/记忆机制）不是调包，讲得出 Trade-off；③ 真实踩坑记录（Windows 并发、路径分隔符、超时重试），有复盘能力；④ 对 LLM 局限性有判断（Flash vs Pro 的成本质量权衡、确定性算法零 LLM 成本优先）。**用具体案例证明，不喊口号。**

**Q33. 未来 1-2 年 Agent 的瓶颈在哪？**
> 回答要点：可答方向：① 可靠性与评测——Agent 长任务成功率低，评测体系缺失（你怎么证明你的 Agent 变好了？）；② 记忆与上下文——长会话的成本和质量；③ 安全——自主工具调用时代的权限与注入；④ 成本——推理成本压不住就无法规模化。结合自己项目：三层自纠错就是在补可靠性，评测是我项目的下一步。

**Q34. 给你一个业务线从 0 到 1，优先级怎么排？**
> 回答要点：骨架：先业务闭环（最痛场景跑通，哪怕丑）→ 再可靠性（失败率/人工干预率指标）→ 再规模化（成本/并发/可观测）→ 最后锦上添花（多 Agent/炫技功能）。对应自己项目哲学："功能不堆砌，核心闭环后做生产化分析"（notes/feature-philosophy-production-focus.md）。

**Q35. 学习能力怎么证明？（面试官视角软素质题）**
> 回答要点：这个项目本身就是证据——一个月从 LangChain 入门到手写 StateGraph 工程化；学习方法论：AI 案例 → 删代码 → 手写复现（强制从"读懂"变"会写"）；面试复盘文化（.learnings/ 30+ 篇复盘笔记）；对标学习（nashsu 13k star 项目逐项对照）。表达公式：**场景 → 我的方法 → 结果/证据**。
