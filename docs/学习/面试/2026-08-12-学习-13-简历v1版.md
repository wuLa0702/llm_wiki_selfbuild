## 项目经历

### LLM Wiki 知识编译系统（自研全栈） · 2026.06 - 至今

**技术栈**：Python · LangGraph · LangChain · FastAPI · ChromaDB · SQLite · React 19 · SSE · MCP

**项目背景**：传统 RAG 每次查询重新分块、结论零累积、回答无法溯源，资料越多成本越高。本项目目标是让知识沉淀、可追溯、越用越厚——一次编译、多次查询，回答能指到原始素材。

**核心工作**：

- **设计编译器模式的知识摄入管线**：两步 CoT 编译（先结构化分析出页面拆分计划，再按计划生成页面），失败自动降级单步模式保闭环；SHA256 增量缓存跳过未变更源文件；注入 index-summary 替代全量索引，摄入 token 对比全量注入节省约 80%（设计估算，待生产数据复核）。

- **手写 9 节点 LangGraph 状态机替代官方 ReAct**：在标准 ReAct 循环上叠加三层自纠错机制——L1 预防（步数熔断 + 工具动作去重）、L2 检查（工具输出质检）、L3 反思（LLM 修正计划后重跑）；对比裸 ReAct，无效工具调用降低约 60%（开发期对比测试数据，可复现）。

- **构建双轨记忆体系 + 混合持久化**：用户驱动的 Attention Sink（显式锚定 + 置信度衰减淘汰）与系统驱动的 Working Memory（5 槽位增量合并）并行；MemorySaver 管运行时、SQLite 管重启恢复；超 40 条消息自动 LLM 摘要压缩，关键记忆跨摘要存活。

- **实现混合检索 + 知识图谱**：BM25（CJK Bigram 分词 + 标题加权）与向量（Chroma 384-dim）双路召回 + RRF 融合排序；wikilink 自动构建知识图谱（4-Signal 关联度 + Louvain 社区发现 + 洞察引擎），纯确定性零 LLM 成本。

- **完善生产级安全与交互**：路径穿越统一校验真源 + 目录隔离（raw 只读 / wiki 可写）+ LLM 输出白名单 + bcrypt 门禁；风险分级 HITL（只读工具自动放行、风险操作中断审批、默认 fail-closed）；SSE 流式对话 + React 19 SPA；8 个 MCP 工具（stdio / HTTP 双模式）供外部 IDE 即插即用。

**项目成果**：

- 完整前后端闭环，PyInstaller 桌面打包（单实例锁 + 崩溃兜底）
- 754 个后端 pytest（LLM 全 mock）+ 81 前端测试 + 22 E2E 全绿
- 无效工具调用降低约 60%（对比裸 ReAct，开发期对比测试）
- 摄入 token 节省约 80%（设计估算，待生产数据复核）
- 知识页面全部带 sources 溯源，图谱 / 社区 / 洞察自动生成
