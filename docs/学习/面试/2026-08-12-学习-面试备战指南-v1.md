## 一、核心认知（P0：先建立正确观念）

> ⚠️ **最大的误区**：把 Agent 当八股学，背定义。
>
> **真相**：Agent 面试考的是**系统设计能力 + 项目追问链**。面试官要听你发现问题、解决问题的真实故事。

| 认知 | 说明 |
|------|------|
| **项目 > 八股** | 一个讲得透的好项目，比背 100 道八股有用 |
| **追问链 > 知识点覆盖** | 面试官会顺着你的项目一路深挖 |
| **复盘 > 刷题** | 面试后整理逐字稿，更新简历和追问链 |
| **差异化 > 同质化** | 人人做 RAG，你讲"wiki 语义化存储"——这是卖点 |
| **现在就开始** | 先投中小厂攒经验，用面试校验水平 |

## 三、项目准备（P0：核心中的核心）

### 3.1 项目选型：LLM Wiki（单 Agent 语义化存储）

**为什么选这个**：
- **差异化**：不做烂大街的 RAG，做"文档编译成 wiki"——面试官眼前一亮
- **有真实深度**：单 Agent StateGraph + 两步 CoT 编译 + WikiGraph 图 + 三角定位查询，每个都有东西讲
- **完整闭环**：Ingest → 编译 → 图 → 问答 → 质量检查，一条链路跑通

**项目一句话描述**：
> 把非结构化资料编译成互链的结构化 wiki 页面（而非塞进向量库），单 Agent 在 wiki 上问答，图关系提供语义关联。

### 3.2 wiki 的 5 个核心卖点（面试要讲的）

| 卖点 | 为什么是卖点 |
|------|-------------|
| **wiki 存储 vs RAG** | 核心差异化：语义上下文保留、可编辑、可审计，多出图关系维度 |
| **单 Agent StateGraph** | 手写 LangGraph 10 节点，证明懂 Agent 编排而非调 API |
| **两步 CoT 编译** | Ingest 管道：先分析再生成，结构化输出保证页面质量 |
| **WikiGraph 图关系** | RAG 没有的维度：wikilinks + 社区 + 洞察 |
| **查询三角定位** | 不依赖向量也答准，最小依赖可部署 |

### 3.3 项目追问链（面试官会怎么问）

> 🎯 **核心原则**：每个点都要能往下挖 3 层。完整五层追问链见 `docs/学习/面试/2026-08-12-学习-项目追问链-v1.md`。

```
第 1 层：业务层 —— 解决什么业务问题？为什么不用 RAG？
第 2 层：架构层 —— 整体架构？为什么单 Agent？wiki 存储怎么做？
第 3 层：实现层 —— 两步 CoT？图怎么建？查询怎么定位？记忆怎么做？
第 4 层：效果层 —— 怎么评估？782 测试？bad case？
第 5 层：优化层 —— 不足？向量关了？成本？安全？
```

## 四、简历优化与埋点（P1）

### 4.1 埋点策略

**怎么做**：简历上每写一个技术点，都问"面试官会怎么深挖？"，提前准备完美答案，故意留钩子。

**例子**：
- 简历写"自研 wiki 语义化存储，非传统 RAG"
- 提前准备：为什么不用 RAG？wiki 和 RAG 的区别？图关系怎么用？查询怎么不做向量也答准？782 测试怎么来的？

### 4.2 STAR 法则展开链

每个项目点按 STAR 展开，一环套一环：
```
S（场景）→ 背景/痛点 → T（任务）→ 目标
→ A（行动，重点）→ 为什么调研这个方案？对比过哪些？做了什么优化？
→ R（结果）→ 提升多少（有数据）？不足？还想怎么改？
```

### 4.3 技术深度原则

> ❌ 堆名词，问到只能答个大概。
> ✅ **讲透一个点 > 浅尝十个点**。每个技术点准备一个"背景→问题→方案→结果"小故事。

## 九、项目场景评估与加固计划（P0）

### 9.1 场景评估：wiki 作为独立项目，不换

> 📌 结论：LLM Wiki 是**独立可讲的完整项目**（单 Agent + wiki 存储），与 multi_agent（多 Agent）是两个独立项目——面试可选讲其一，或讲"单体→多 Agent"演进故事。

**定位**：**wiki 语义化存储 + 单 Agent 编译/问答**——差异化卖点是"非 RAG"，面试官见过的都是 RAG 项目，这是突破口。

| 优先级 | 事项 | 状态 | 面试价值 |
