## §1 总（30s）

> "Ingest 管道是把**非结构化资料编译成结构化 wiki 页面**的核心：FolderImporter 扫描 → SHA256 缓存去重 → 隐私检测 → **两步 CoT**（Step1 结构化分析 → Step2 LLM 生成页面）→ WriteTool 写库 → 更新导航 → 图缓存失效重建。全程带队列、断点重试、失败降级。"

## §2 分（60-90s）

**① 两步 CoT 为什么比一步好**：
- 一步直接"生成页面"容易漏结构；两步先分析（AnalysisOutput 结构化）再生成，**先想清楚再写**
- 结构化输出（Pydantic schema）保证页面格式统一、可解析

**② 工程化细节**：
- **SHA256 增量缓存**：相同内容不重复编译（`ingest_cache` 表）
- **重试降级**：LLM 瞬时失败重试 → 降级（不打断整批）
- **队列管理**：`ingest_queue` + 取消/重试/清理接口

**③ 隐私**：导入前隐私检测（privacy_rules 匹配），敏感内容标记不写入

## §3 流程图

```
raw/ 或 sources/ → FolderImporter 扫描
  → SHA256 缓存检查（命中跳过）
  → 隐私检测（rules 匹配）
  → 两步 CoT：Step1 分析 → Step2 生成页面（结构化输出）
  → WriteTool 写 wiki/ → 更新导航 → 图缓存失效 → 后台 rebuild_graph
  → 队列状态回报（progress/active/failed）
```

## §4 总（20s）

> "Ingest 不是简单塞库——是**内容质量的第一道闸**。两步 CoT 保证页面结构化，缓存避免重复烧钱，队列让大批量可管理。它是整个 wiki 存储的地基。"
