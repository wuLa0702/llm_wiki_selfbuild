## §1 总体架构

**定位**：LLM Wiki 是**单 Agent 的 wiki 语义化存储**项目——不是 RAG（不做向量检索为主的问答），而是把非结构化资料**编译成结构化 wiki 页面**（wikilinks 互链 + 图关系 + 图社区洞察），Agent 在编译后的 wiki 上做问答。核心卖点：**数据从"塞进向量库"变成"组织成 wiki"**。

```
┌─────────────────────────────────────────────────────┐
│ 前端（React + 内嵌静态页）                              │
│   对话 ChatPage · 管理端 · Wiki 浏览                    │
└──────────────┬──────────────────────────────────────┘
               │ REST + SSE（/v1/agent/chat/session）
┌──────────────▼──────────────────────────────────────┐
│ 后端 FastAPI（api/）                                  │
│   路由（auth/chat/graph/ingest/lint/pages/misc）       │
│   中间件（CORS + X-Request-ID）· 可选密码门鉴权         │
│   ┌──────────────────────────────────────────────┐  │
│   │ Agent 层（agent/ + core/graph/）               │  │
│   │   StateGraph 单 Agent：intent → 推理 → 记忆     │  │
│   │   → HITL审批 → 工具 → 自修正 → 摘要              │  │
│   │   MemorySaver checkpointer + SQLite 备份        │  │
│   └──────┬──────────────┬──────────────┬─────────┘  │
│   ┌──────▼──────┐ ┌─────▼──────┐ ┌─────▼────────┐   │
│   │ 工具层 tools │ │ 领域 core   │ │ 数据层 db    │   │
│   │ Read/Write  │ │ compiler/  │ │ WikiRepository│  │
│   │ Search/Lint │ │ ingest/    │ │ schema.py    │  │
│   │             │ │ query/     │ │ (13 表)      │   │
│   └─────────────┘ │ search/    │ └──────────────┘   │
│                   │ graph/     │                     │
│   ┌───────────────┼────────────┼───────────────┐    │
│   │ LLM（llm/）     │ 记忆（agent/memory）        │    │
│   │ LLMAdapter     │ AttentionSink · WM · 摘要   │    │
│   └───────────────┴────────────┴───────────────┘    │
└─────────────────────────────────────────────────────┘
```

### 依赖单向

```
main.py → api → agent/core → {llm, db, tools, models}
                              ↘ utils（path_resolver/config_manager）
```

- 禁止反向依赖；`agent/planning/graph.py` 内惰性 import 防循环
- **两套 graph 别混淆**：`agent/planning/graph.py` = LangGraph StateGraph（Agent 编排）；`core/graph/graph.py` = WikiGraph（wiki 页面关系图，确定性算法，与 LangGraph 无关）

## §3 数据流（一次对话）

```
用户消息 → api/routes/chat.py（校验+会话定位）
  → agent/session.py chat_stream_session（MemorySaver 恢复状态）
  → StateGraph 节点链：
     intent_classifier（意图识别）
       → agent（call_model 主推理）
       → extract_wm（提炼工作记忆）+ wm_eviction（淘汰）
       → [有工具调用] validate_tool（步数熔断+去重）
         → approve（HITL 审批：只读放行 / 风险工具 interrupt 等待）
         → tools（Read/Write/Search/Lint）
         → verify_result（结果质量校验）
           → [差] reflect（LLM 反思回 agent）
         → summarizer（上下文压缩）→ END
  → SSE 事件流（token/tool_start/tool_end/tool_approval_needed/intent/done/error）
  → 前端渲染
```

## §4 核心决策

| 决策 | 选择 | 理由 / 权衡 |
|------|------|-------------|
| **单 Agent vs 多 Agent** | 单 Agent（四模块：perception/planning/memory/action）| 领域单一（wiki 编译+问答），不拆多 Agent；拆多 Agent 的代价（成本 2-8×/延迟）不划算 |
| **存储 = wiki 而非 RAG** | 非结构化资料 → 编译成结构化 wiki 页面（wikilinks 互链 + 图关系）| 避免 RAG 的"检索碎片、答非所问"；wiki 页面有语义上下文、可编辑、可审计 |
| **查询三角定位** | SQLite 搜索 + BM25 + WikiGraph 图扩展 + LLM 读 index.md 兜底 | 不依赖向量也能答准；wiki 图关系弥补全文检索 |
| **两层记忆** | AttentionSink（锚定/衰减）+ WorkingMemory（槽级合并）+ summarizer | 长对话防上下文丢失，Attention Sink 锚定关键信息 |
| **三层自修正** | validate_tool（熔断+去重）→ verify_result（质量校验）→ reflect（LLM 反思）| 工具调用/结果/推理三处兜底 |
| **HITL 审批** | 工具风险分级：只读放行、风险工具 interrupt() 暂停等审批 | 防误操作，人工在环 |
| **搜索三模式** | BM25（默认）/ vector / hybrid；向量默认关、自动降级 BM25 | 最小依赖可部署，向量是可选增强 |

## §5 依赖与限制

- **Python 3.11+ / LangGraph / FastAPI / sqlite3**；向量引擎（Chroma+sentence-transformers）可选
- **语义搜索当前版本关闭**（2026-08-01）：去依赖 + 降级 BM25，前端提示
- **单 Agent 上限**：单任务递归 50；工具调用步数熔断
- **数据规模**：`wiki_pages` + `page_links` + 图缓存；大资料库靠 Ingest 管道分批
