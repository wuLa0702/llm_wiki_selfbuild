# 文档规范（docs 通用规则）

> 本文件是 docs/ 下**所有文档的格式规则唯一载体**——后续要改规则只改这里。
> 适用范围：`docs/` 目录下所有 Markdown 文档。
> 不适用：`docs/图片和附件/`（图片/OCR 原始附件，不参与格式约束）、仓库根目录的 CLAUDE.md / AGENTS.md / README.md（工程约定文件，保持各自格式）。

---

## 1. 文件名规则 🔴 v2

1. **docs 下所有文档一律中文名称**（方便一目了然）：
   - ✅ `docs/学习/2026-07-27-学习-agent架构图.md`
   - ❌ `docs/agent-architecture-diagrams.md`
2. 附件（图片/OCR）保留原名，不做中文约束（改名会破坏文档引用）。
3. 版本后缀（`-v1` / `-v2`）是文件名的一部分，保留。
4. **创建时间戳前缀（2026-08-06 确立）**：所有文档文件名统一加**创建日期前缀** `YYYY-MM-DD-`：
   - 格式：`YYYY-MM-DD-类型-主题-vN.md`，如 `2026-07-22-决策-迁移审计.md`
   - **日期 = 文档创建日**（git 首次提交日；后续改名/迁移沿用原日期，不随更新时间变）
   - 模板类（`规则/功能模板.md`）除外
   - **区分同功能多版本文档**：同类型主题多文档并存（不同日期开发、功能有交集）时，**以创建日期最新者为现状真相**；旧版本文档标注「已被 YYYY-MM-DD 版覆盖」或归档 `docs/归档/`
   - 附带收益：文件名按字典序排序 = 时间序，新旧一目了然

## 2. 文档头模板（每个文档最顶部，标题之下） 🟠 v2

所有文档必须包含以下四要素，顺序固定：

```markdown
# 文档标题

> 📋 **规范**：遵循 `docs/规则/文档规范.md`
> 📌 **更新时间**：2026-08-12
> 📝 **版本变更记录**（永久保存，只追加不删除）：
> | 版本 | 日期 | 具体改动（精确到二级标题） |
> |------|------|------|
> | v3 | 2026-08-12 | §2 目录结构：新增 xxx；§3.2 状态设计：xxx 改为 xxx |
> | v2 | 2026-08-12 | §1 技术栈：xxx |
> | v1 | 2026-08-12 | 初版 |

## 目录

- §1 …
- §2 …

---

正文开始
```

**要素说明**：
| 要素 | 要求 |
|------|------|
| 📋 规范 | 固定引用 `docs/规则/文档规范.md`，不重复抄规则 |
| 📌 更新时间 | 每次改动都更新为当天日期 |
| 📝 版本变更记录 | **永久保存**：从 v1 到当前全部保留，只追加不删除、不归档；每条必须写「改了什么章节（至少二级标题）+ 改了什么内容」，禁止「本次改动摘要」式泛写 |
| 目录 | 文档内小节导航（标题+链接），章节多时用表格 |

## 3. 版本记录规则 🔴 v9

- **唯一位置**：文档头的「📝 版本变更记录」表即完整版本历史，**正文不再单独维护版本表**（避免双份维护；已有正文版本表的文档，迁移时并入文档头）。
- **永久保存**：记录从 v1 到当前**全部保留**，只追加、不删除、不归档到别处。
- **细节要求**：每条记录必须写明「改了哪个章节（至少精确到二级标题 §X.Y）+ 改了什么内容」；多个改动点用分号分隔逐条列出。❌ 禁止写「本次改动摘要」「更新文档」等泛话。
  - ✅ `§3.2 状态设计：xxx 改为 xxx；§4 页面布局：新增 xxx`
  - ❌ `v2 | 2026-08-12 | 更新状态管理`
- 版本号与文件名 `-vN` 保持一致；大改升级文件名版本号，小修不动。
- 每次修改：①文档头更新时间更新 ②版本变更记录表追加本次（含细节）③文件名版本号升级（大改）或保持不变（小修）④目录同步。
- **正文版本标记**：被改动章节的**一级/二级标题**（`##`/`###`）行末标注**版本标识**（Emoji 色点 + 版本号），醒目区分新旧（解决「翻正文看不出哪节是新改的」）：
  ```markdown
  ## 2. 目录结构 🔴 v2.8
  ```
  - **只保留最近三次**：当前版本 = 🔴 红点、上一版本 = 🟠 橙点、上上版本 = ⚪ 灰点
  - **超过就去标记**：标注的版本号已不在最近三次内（如文档已到 v10，章节仍标 v7）时，本次维护中移除该标识
  - 一章节多次被改：只标最近一次版本号，不叠标
  - 渲染兼容：Emoji 全平台原生显示（GitHub / Typora / Obsidian / PyCharm 大纲均无兼容问题）

## 4. 内容规则 🔴 v8

1. 优先级/状态标注统一符号：✅ 已完成 / ⏳ 待做 / ⚠️ 存疑待核实 / 🔧 已修正 / 📊 经验估算 / 📌 经验来源
2. 中文为主，术语可保留英文原文（如 SSE / Redis）。
3. 更新维护时：**先改文档头**，再改正文，最后更新版本表。
4. **功能更新日志维护规则**（2026-08-10 确立）：功能变更记录统一写入 `docs/功能更新日志.md`（双表：变更流水 + 功能域状态，含 git 版本与时间范围）。约定：
   - **触发**：阶段性批量——每批功能提交收尾时更新（约 1 分钟），不逐 commit 更新
   - **版本号**：commit 短哈希 8 位（可 `git show` 回溯），不引入 tag 体系
   - **信息源**：git log 命令模板（日志文档 §2），**禁止翻代码**确认功能变更
   - **对比**：查看自上次记录版本号以来的变更，`git log <旧hash>..<新hash> --oneline` 核对
   - **同步动作**：流水表新增一行（倒序置顶）→ 域状态表同步该域最近更新/版本/时间范围

## 5. 每次更新维护的固定动作（Checklist） 🔴 v9

- [ ] 更新时间 → 今天
- [ ] 版本变更记录表 → 追加本次（**具体到二级标题细节**），旧记录一律不动
- [ ] 文件名版本号 → 大改升级（-vN），小修不动
- [ ] 目录 → 章节有增删时同步
- [ ] 正文 → 被改章节标题旁标本次版本号（🔴/🟠/⚪ 三色点，见 §3「正文版本标记」），并移除不在最近三次内的旧标识
- [ ] **索引同步（2026-08-06 治理定稿）→ 新增/改名/归档/删除文档时，同步更新 `docs/索引.md` 一行**（索引是 docs 唯一入口）
